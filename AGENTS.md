# Project overview

Text Scanner is a local Tkinter desktop application that turns documents into a frequency-sorted vocabulary. It supports source-text editing, occurrence highlighting, translations, learned-word tracking, filtering, sorting, and CSV import/export.

The application is a single-process GUI program with no backend, database, package manifest, or independently installable Python package. Source comments, docstrings, and UI text are in English.

## Project structure

- `main.py`: minimal development entry point.
- `textscanner/app.py`: Tkinter application, UI construction, events, shortcuts, and coordination between modules.
- `textscanner/documents.py`: word extraction and document-format parsing.
- `textscanner/library.py`: word counts, learned words, filtering, sorting, and vocabulary actions.
- `textscanner/storage.py`: translation/session persistence and CSV I/O.
- `textscanner/theme.py`: self-contained light and dark color palettes.

Keep parsing, vocabulary logic, and storage independent of Tkinter. GUI behavior belongs in `App`; reusable non-GUI behavior should stay in the appropriate helper module.

# Technology and runtime

The project uses the Python standard library, including `tkinter`, `csv`, `json`, and `html.parser`. No minimum Python version is declared.

Document parsers are optional and imported only when their format is opened:

```bash
pip install pypdf
pip install striprtf
pip install python-docx
pip install ebooklib
pip install html2text
```

Install only the parsers needed for the formats being used. HTML and EPUB have a standard-library HTML cleanup fallback when `html2text` is unavailable. LIT files must be converted externally, for example with Calibre.

Run the development entry point with:

```bash
python main.py
```

Tkinter requires a working Tk installation and graphical display. The previous external `theme.colors` dependency has been removed.

For a syntax-only check:

```bash
python -m py_compile main.py textscanner/*.py
```

This creates `__pycache__` directories; remove generated bytecode if it is not wanted. No automated test suite, linter, formatter, CI configuration, or packaging command is configured. Do not add test files unless requested.

# Application behavior

- Opening a document replaces the current workspace after confirmation. Rescanning the edited source replaces word counts while retaining learned status for words still present.
- The To learn tab excludes learned words; Learned contains only learned words. Count sorting is descending by default with alphabetical tie-breaking. Word and translation column headings are sortable.
- The filter searches both words and loaded translations. Selection supports normal Tkinter multi-selection, Ctrl+A in the table, bulk learned/unlearned actions, and removal.
- Clicking a word highlights whole-word source matches. Repeated clicks cycle through matches.
- CSV export writes `word,occurrences,translate` for the active tab, independent of the current filter. Import keeps the larger existing/imported count and applies the active tab's learned status.
- Shortcuts include Ctrl+O (open), Ctrl+S (export), Ctrl+N (new), Ctrl+F (filter), F5 (rescan), Escape (clear filter/selection), Delete (remove selected), and Ctrl plus/minus/0 (zoom).

# Persistence and resources

- `dict.json` is optional. It is resolved relative to PyInstaller `_MEIPASS` when packaged and otherwise relative to the process working directory. Missing or invalid content produces a warning and empty translations.
- `state.json` is created on close in the process working directory. It stores geometry, complete source text, counts, learned words, active tab, theme, zoom, and source path. Missing or invalid state becomes an empty session.
- Session writes use a temporary file followed by `os.replace`.
- The complete source text in `state.json` may be sensitive. Do not commit it or copy it into logs or fixtures without user consent.
- Filesystem writes are limited to the established session file and user-selected export paths.

# Code style and verification

Follow the existing `snake_case` conventions, sparse annotations, module-level helpers, and internal `App` method names prefixed with `_`. Keep optional parsers independently optional and report missing support through the existing `ValueError`/messagebox flow. Use the established Tkinter/`ttk` widgets and theme palettes rather than adding another UI framework.

There is no automated test suite. After behavior changes, run the syntax check, exercise pure document/library/storage helpers without constructing `App`, and manually exercise affected GUI flows with a real display. Avoid constructing Tk windows in a headless environment. Verify scanning, filtering, selection actions, occurrence navigation, CSV round-trips, session restoration, theme switching, and zoom when those areas change.

PyInstaller `_MEIPASS` handling exists for `dict.json`, but no spec, bundled-resource configuration, or executable build command is present. Packaging work must explicitly include the package modules and translation resource, choose a writable session location, and verify startup on each target platform.
